Fusion 360 to ROS 2 URDF: The Real-World Guide

January 2026 · 10 min read

The real-world guide to exporting complex, nested Fusion 360 assemblies into ROS 2 without losing your mind or your coordinate systems.

Read article →

Complementary Documentation for: fusion2urdf-ros2 by dheena2k2 ↗

The standard README assumes you are a Linux pro and your CAD file is perfect. In reality, you will hit weird structure issues and terminal errors. This guide covers the "hidden steps" required to get a complex, nested Fusion 360 assembly into ROS 2.

1. Preparing the CAD (The "Cut & Paste" Method)

You do not need to flatten your entire assembly into a list. You can keep your Nested Structure (components inside components), but you must ensure the physics bodies are in the correct container. The most common mistake is having the robot's chassis bodies floating in the generic "Main File" rather than inside the base_link component.

Step 0: Break All Constraints First

Before you move anything, you must free your components from Fusion's constraints. If you try to Cut & Paste a body that is locked, Fusion will error out.

  1. Break Links: If you see a "chain link" icon on any component, right-click it and select Break Link. This disconnects it from external files.
  2. Delete Rigid Groups: Look in the browser for a folder named "Rigid Groups". Delete it entirely. Do not use Rigid Groups for ROS.
  3. Unground Everything: Look for any component with a "Pushpin" icon (red or gray). Right-click and select Unground.

Figure 1: The correct hierarchy. Note that bodies are inside base_link, not floating at the top level.

Step A: The "Base Link" Container

  • Create the Component: Right-click the top-level file name in the browser and select New Component.
  • Name it: Name it exactly base_link.
  • Note: If Fusion names it base_link (1), you have a duplicate name hidden somewhere. Find it and delete or rename it, or the script will fail.

Step B: Moving the Bodies (Cut & Paste)

Your chassis parts (plates, brackets, screws) are likely scattered as "Bodies" inside various folders. You need to move them into the base_link component.

  1. Activate Base Link: Click the small circle next to your base_link component to activate it.
  2. Enable Body Selection: By default, Fusion selects faces. Go to the top toolbar: Select > Selection Priority > Select Body Priority.
  3. Select & Cut: Select all chassis bodies (hold Shift). Press Cmd+X (Mac) or Ctrl+X (Win).
  4. Paste: Press Cmd+V (Mac) or Ctrl+V (Win).
  5. Result: The bodies move from the old folder into base_link, keeping their exact position in 3D space intact.
  6. Ground: Right click on base_link and select "Ground to Parent".

2. Joint Configuration

  • Use As-Built Joints (Shift + J): Since your design is already assembled in the correct shape, do not use standard "Joints" (which move parts). Use "As-Built."
  • Selection Order: When making a joint, select the Child (moving part) first, then the Parent (stationary part). Example: click Wheel → click base_link.
  • Types: Revolute for wheels and arms; Rigid for locking sub-assemblies together (e.g. locking a LIDAR sensor to the chassis).

Figure 2: The As-Built Joint menu. Ensure the correct Motion Type is selected.

3. Terminal & Script Installation

If you are not used to the command line, the standard installation instructions can cause zsh: parse error or No such file errors.

Common Error 1: The "Placeholder" Trap

Error: cd: no such file or directory: <path to fusion2urdf-ros2>

Cause: The text <path to...> is a placeholder.

The Fix: Type cd (with a space), then drag and drop the folder from Finder/Explorer into the terminal window.

Common Error 2: The "Wrong Directory"

Error: cp: ./URDF_Exporter_Ros2: No such file or directory

The Fix: Always check where you are before copying. Run ls. If you don't see the script in the list, you are in the wrong folder.

The Correct Command Sequence (Mac Example)

# 1. Go to your downloads (or wherever you cloned it)
cd ~/Downloads/fusion2urdf-ros2

# 2. Verify the file is actually there
ls
# (You should see 'URDF_Exporter_Ros2' in the output)

# 3. Copy the script to the Fusion 360 Script folder
cp -r URDF_Exporter_Ros2 "$HOME/Library/Application Support/Autodesk/Autodesk Fusion 360/API/Scripts/"

4. Final Checklist Before Export

  • Name Check: Top component is base_link (no space, no (1)).
  • Body Check: base_link contains the chassis bodies (not sitting in a generic "Component1").
  • Constraint Check: All Rigid Groups deleted; all components Ungrounded.
  • Joint Check: Only Rigid or Revolute joints used. No red/yellow warnings.
  • Orientation: Red axis (X) points Forward. Blue axis (Z) points Up.

QGroundControl Setup

December 2025 · 8 min read

A comprehensive overview of setting up QGroundControl for MAVLink-enabled robots and PX4 stacks for autonomous flight missions.

Read article →

The Summary

QGroundControl (QGC) provides full flight control and mission planning for any MAVLink-enabled robot. The primary goal is to provide an easily editable user interface for the developer to configure. It serves as the primary ground control station for the PX4 autopilot stack.

QGC allows operators to plan complex autonomous missions on a desktop and also provides visual data coming from the vehicle.

Figure 1: High-level connection architecture between QGC and the Vehicle.

Technical Workflow: PX4 Integration

1. Installation

Installation directions at the QGC User Guide ↗.

# Ubuntu Permission Setup (User to dialout group)
sudo usermod -aG dialout $USER

# Remove modem manager (interferes with serial ports)
sudo apt-get remove modemmanager -y

# Install GStreamer (required for video streaming)
sudo apt install gstreamer1.0-plugins-bad gstreamer1.0-libav

2. Initial Configuration

Once QGC is running, connecting a vehicle's flight controller via USB automatically triggers the setup logic. The Vehicle Setup view (gear icon) is where the core configuration happens:

  • Firmware: QGC detects the board (e.g. Pixhawk) and offers to flash the stable PX4 Pro stack.
  • Airframe: Select the specific vehicle geometry (e.g. Hexarotor X, Quadcopter, VTOL) or custom, then "Apply and Restart".
  • Sensors: A guided wizard walks you through calibrating the Compass (rotating the drone on all axes), Gyroscope (holding it still), and Accelerometer.
  • Radio: Requires moving the transmitter sticks to their limits to map channels and set min/max values.
  • Joystick: To enable joystick and disable RC mode, navigate to View → Parameters → search COM_RC_IN_MODE.

Figure 2: Configuring COM_RC_IN_MODE to enable MAVLink joystick control.

3. Flight Modes & Safety

For PX4, you map specific RC switches to flight modes. A common setup involves a 3-position switch configured for:

  1. Position Mode: GPS-assisted hovering (easiest for beginners).
  2. Altitude Mode: Maintains height but drifts with wind.
  3. Return Mode: Automatically returns the drone to the launch point.

4. Mission Planning & Operation

The Plan View allows you to click on the map to place waypoints. For surveying, the "Pattern" tool automates the creation of grid flights for aerial mapping.

During flight, the Fly View displays the live video feed (if configured) and critical telemetry like battery voltage, satellite count, and altitude.

My Perspective

In the robotics ecosystem, the "user experience" is often an afterthought, but QGroundControl changes that narrative. While Mission Planner (the alternative GCS) offers incredibly deep parameters for debugging, QGroundControl shines in its modern, intuitive interface.

For field operations, the ability to run QGC on an iPad or Android tablet is a game-changer. It reduces the amount of heavy gear required and simplifies the pre-flight checklist. The touch-optimized interface makes dragging waypoints and adjusting mission parameters feel natural rather than technical.

Ultimately, if you are developing new vehicle types or need deep log analysis, you might stick to Mission Planner. But for reliable day-to-day operations and a setup workflow that doesn't require a manual to understand, QGroundControl is the superior choice.
